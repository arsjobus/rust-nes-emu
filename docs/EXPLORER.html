CPU

05 / Run it

Launch RuNES

Build an optimized version, then pass a ROM path after Cargo's separator.

cargo run --release -- path/to/game.nes

Or start without a ROM to open the animated static screen and ROM picker.

cargo run --release

Try visual effects by adding flags:

cargo run --release -- game.nes --scanlines --ntsc --curvature

Battery saves sit beside the ROM as .sav. Recording uses FFmpeg with libx264.

06 / A few useful distinctions

Explore the details

Why does one instruction move three pieces of hardware?

The NES CPU and PPU use related clocks. RuNES executes a CPU instruction, accounts for its cycles, then catches the PPU up by three dots per CPU cycle and clocks the APU. Register accesses synchronize devices mid-instruction, which matters for timing-sensitive games.

What does a mapper actually do?

A cartridge can contain more program and graphics data than the console can address at once. Mapper logic selects banks and can provide extra memory or interrupts. In RuNES the mapper is behind the cartridge interface, so CPU and PPU request data without knowing each board's details.

Are visual effects part of the emulated NES?

No. The PPU produces the game's framebuffer. A separate post-processing pipeline can apply effects such as NTSC bleed, scanlines, curvature, bloom, persistence, LUT color, and vignette before SDL presents the image.

Where should I look in the source?

src/main.rs loads arguments and starts the frontend; src/nes.rs coordinates frames; src/bus.rs routes memory and timing; the cpu, ppu, apu, and cartridge folders implement hardware; src/video.rs owns the interactive window loop.
